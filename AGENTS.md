# Project instructions for coding agents

- Read INDEX.md, 01_REQUIREMENTS.md, and DECISIONS.md before changing product behavior. Use 02_ARCHITECTURE.md for accepted technical choices; do not treat proposals as approved.
- Follow the latest direct user decisions over older notes. Requirements control behavior; screenshots and generated artwork are visual references, not behavioral authority.
- Work autonomously on reversible local edits that satisfy approved requirements. Ask only when a material decision is unresolved or a requested action needs approval. Do not add features beyond approved scope.
- Do not publish, deploy, change repository visibility, add external services, or transmit project data beyond explicitly approved destinations without user authorization. The public repository and GitHub Pages destination are approved project goals; do not change repository owner/visibility or publish elsewhere without explicit permission.
- Keep changes focused, preserve existing user work, and update the relevant source-of-truth document when an approved decision changes.
- Verify changes against 05_TESTING_STRATEGY.md. Do not run tests or checks unless the user asks for verification; when asked, report exactly what ran and any limitations.
- Do not claim an unresolved behavior, unrun check, or unconfigured deployment is complete.
